## 2) `location-inner` 的 502px 隐藏溢出

### 2.1 diff（`src/ui/styles/command-dock-sliding.css` L77-107）

```diff
 #command-dock #location-bar.collapsed .dock-popover-content,
 #command-dock #control-panel.collapsed .dock-popover-content {
-  display: flex !important;
+  display: none !important;
+}
+
+/* 保动画：allow-discrete + @starting-style，从 display:none 进出仍有淡入淡出 */
+@supports (transition-behavior: allow-discrete) {
+  #command-dock .dock-popover-content {
+    transition:
+      opacity 180ms ease,
+      visibility 0s linear 180ms,
+      transform 220ms cubic-bezier(0.2, 0.8, 0.2, 1),
+      display 0s allow-discrete 180ms;
+  }
+  #command-dock #location-bar:not(.collapsed) .dock-popover-content,
+  #command-dock #control-panel:not(.collapsed) .dock-popover-content {
+    @starting-style { opacity: 0; transform: translateY(0.55rem) scale(0.985); }
+  }
 }
```

> 为什么不用方案 B（折叠态 inner `overflow:hidden`）：`scrollWidth` 统计的是**滚动溢出区**，
> 加了 `overflow:hidden` 后 502 依旧是 502，只是看不见 —— 过不了本条验收。
> `display:none` 才是真正把隐藏托盘移出布局。

### 2.2 验收数值

折叠态（默认）：

| 卡 | 修前 scrollWidth / clientWidth | 修后 scrollWidth / clientWidth | delta |
|---|---|---|---|
| **location-bar** | **502 / 168** | **168 / 168** | **0** |
| **control-panel** | **202 / 168**（复核报告） | **168 / 168** | **0** |
| data-panel | — | 176 / 176 | 0 |
| scene-panel | — | 176 / 176 | 0 |
| cctv-panel | — | 176 / 176 | 0 |
| global-context-panel | — | 176 / 176 | 0 |

展开态（真实点击 disclosure）：

| 项 | location-bar | control-panel |
|---|---|---|
| collapsed | false | false |
| 托盘 display / opacity | `flex` / `1` | `flex` / `1` |
| 托盘矩形（CSS px） | 544×117 @ (496,494) | 544×163 @ (496,449) |
| 完全在视口内 | 是 | 是 |
| `elementFromPoint(托盘中心)` | `BUTTON`（托盘内元素） | `SECTION`（托盘内元素） |

托盘动画（同一 CSS 改造后仍在）：开 → `display none→flex`，`getAnimations()` 有 `opacity` / `transform`
两条 CSSTransition；细采样那轮 opacity 0 → 0.452 → 0.639 → 0.957 → 1（本机 headless rAF 被 GPU 帧占满，
采样点稀疏，另一轮压缩采样只落到 0 → 0.978，但 CSSTransition 计数始终 ≥2）；
关 → opacity 1 → 0.479 → 0.005，约 200ms 后 `display:none`。折叠/展开反复 1 次后 scrollWidth 仍 168/168。

> 注：`@supports (transition-behavior: allow-discrete)` 不成立时（旧浏览器），块内 `transition` 整条失效，
> 托盘退化为「直接显示/隐藏」——`display:none` 的本职（不撑 scrollWidth）不受影响。

### 2.3 顺带修掉的两个**既有**缺陷（不是本次改动引入，A/B 已证明）

1. **托盘被裁掉**：`html.gev-gl-on .gev-lc { overflow: hidden !important; }` 把
   `.dock-popover-content`（`bottom: calc(100% + …)`，整块在卡壳之外）整块裁掉 ——
   修前修后注入旧规则都测到 `elementFromPoint(托盘中心) = CANVAS`、托盘区域平均亮度 0.147（= 地图）。
   这直接违反本条验收「展开态托盘仍能正常显示」，因此加一条例外：

```diff
 html.gev-gl-on .gev-lc { overflow: hidden !important; }
+html.gev-gl-on #command-dock > .gev-lc { overflow: visible !important; }
```

   修后：托盘区域平均亮度 0.147 → **0.0801**（真的画出来了），`elementFromPoint` 命中托盘子元素。

2. **托盘 scrim 太淡**：0.22 单层 scrim 下城市名药丸像素法只有 **3.77:1**（<4.5）。
   托盘不是玻璃面、不在 9 卡之列，给它自己一层无障碍 scrim（仍无 backdrop-filter）：

```diff
+html.gev-gl-on #command-dock .dock-popover-content {
+  background: rgba(5, 9, 14, 0.86) !important;
+}
```

   复测：托盘文字最小 **8.85:1**。
