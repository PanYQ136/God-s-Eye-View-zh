### 1.2 关键路径（改后，prod 冷启动，ms，navStart 口径）

```
0       nav
~640–3200  Cesium.js 下载+求值（defer 后与 module chunk 并行下载；仍是首帧前的主线程块）
~640–3300  主 chunk 求值 → gate:frame:first → cine:go(base-first)（相机首帧放行，不等 Tiles）
~700–3500  Viewer(0.4–1.0s) → basemap:setStack:begin（stackProbe race ≤700ms）
~1.0–4.0s  stack:imagery:ready → scene:ready → controls(lc 卡片 mounted) → data → tools
3.5–5.9s   ★ mask:input-released（卡片可点；判据 = lc.mounted + 画面非纯色）
5.4–8.6s   gate:view:content(清晰) → +SETTLE 900ms + tilesLoaded → decide → 270ms 淡出
           ★ gate:mask:gone（B5 视觉门；中心 640×420 std 32.8–33.5 / uniq 51k–55k）
~12–19s    photoreal:ready（3D Tiles 后台完成，globe.show=false）
```

**两条硬结论**：
1. **3D Tiles 已不在首屏关键路径上**（`scene.js` 只发起不 await；gate 的三条 tileset 判定已删）。
2. 「≤5s」的物理瓶颈是 **Cesium.js 的下载+求值**（0.64–3.2s，方差来自磁盘/传输）与
   **底图金字塔到首块影像**，不是 3D Tiles。

## 3. 决策 A（模块图拆分）的实测结论：**几乎零收益，不要再投**

- 拆分前 `dist/assets/index-*.js = 2,673,080 B`；拆分后 `2,620.91 kB`（-52 kB，-2%）。
- 原因：12 个入口本来就是薄壳（gev-perf 4.3kB / layer-limits 5.2kB / mobile-ui 2.2kB /
  panel-win 7.0kB / graphics 11.2kB / dossier 18.5kB，合计 **~48kB**）。
  **2.67MB 是 `main.js` 拉起的 App 图本身**（scene/lc/data/tools/各面板），不在入口层。
- 结论：真正能动的只有「App 图内部再切」（风险高、动首屏耦合），或把 Cesium 从经典脚本改为
  按需 chunk（R8-2，见 §6）。**A 作为「入口拆分」已被本轮证否。**

## 5. 未达成项（不隐藏）

1. **`interactive ≤5s` 6/6 未达成**：终态 3/6（中位 5.15s）；本卡期间最好的一批（p7ad3）是 6/6
   （中位 4.41s），但那一批的 B5 是 2/6（遮罩撤在空 globe 上）。**两条门在同一段关键路径上互相拉扯**：
   把 B5 修正（等 `tilesLoaded`）整体后移 ~1.2s，卡片可点因为共享 `gate:eval`/金字塔而同步被拉后。
2. **B5 ≤8s 只有 3/6**：终态 B5 7.40–8.61s（中位 8.02s）；视觉 6/6 PASS。
3. **无 >100ms 帧未达成**：终态每跑 0–2 个（96.5–128.6ms），族别与 C6 相同（Cesium 瓦片上传/着色器 link）。
4. **fps 与 C6 同现象**：本轮实测 105–125fps（显示端 vsync ≈120Hz），不是 50–60；
   若验收要求落在 50–60，需要先统一测法（当前 rAF 采样直接反映面板刷新率）。
5. **reveal 偶发空 globe 的根因仍未闭环**：本轮用「`tilesLoaded` + 读数新鲜度」把现象压到 0/6，
   但没有证明「父瓦片丢弃」不会被别的时间点触发（例如 photoreal 升级后）。建议单开卡做
   「空帧检测 + 自动重绘」的持久化保护。

## 6. 下一步（按收益/成本排序，均需 lead 决策）

| # | 动作 | 预期收益 | 成本/风险 |
|---|---|---|---|
| **S1** | Cesium 静态资源压缩分发（`dist/cesium/*` gzip/brotli；当前 prod 实测传输 1.70MB 但求值仍是 3.0s 主线程块）+ 判定是否可拆成按需 chunk | 首帧前 −0.5–2.0s（直接决定 ≤5s） | 中：动 CDN/服务端 + 首帧依赖 Cesium 的先后 |
| **S2** | 决策口径：允许「底图为粗 LOD 时放行输入」（去掉「非纯色」下限，只要求 `stack:imagery:ready`） | 卡片可点 −0.3–1.0s，可望 6/6 | 产品口径：可能出现 ~1s 低清画面（有状态胶囊提示） |

| **S4** | R7 ion endpoint 延到 `stack:imagery:ready` 之后 | −0.1–0.6s（少一条同源长连接） | photoreal 再晚 1–3s（B 类） |
