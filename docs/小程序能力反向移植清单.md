- **`grid` 为什么固定 2**：`grid=N` 就是 N² 次高德请求（`cn-live.js:121` 的 `BATCH=4` 分组并发）。2 → 4 次，3 → 9 次。叠加 180s 刷新、服务端 `TRAFFIC_TTL` 也是 180s，几乎每轮都穿透缓存直打上游，用 3 风险明显更高。小程序 `cn.js:54` 的注释也是「2×2 = 4 次请求，太大容易打爆配额」。

## 4. 实施约束（踩过的坑，务必写进任务）

1. **两类落点别混**：A1–A4 数据图层走正式 catalog（§1.2）；A5/A7 的 UI 浮层写 `src/gev-cn-*.js`，由 `boot-defer.js` 的 `DEFERRED` 动态装载（不是 index.html 静态 script），**删掉该行即可完整回滚浮层**；正式图层做不到这种回滚。不要改 `src/app/application.js`、`src/app/viewer.js` 或 Cesium 主链。浮层模块顶层不读 seam，首次请求放到就绪之后，避免与首帧争带宽。
2. **坐标系（最容易出错，必须按端点分别处理）**：Cesium 用 WGS-84；`cn-live.js` **全文零 import/require、零坐标转换**，返回上游原值或按你的入参算出的值。
   - `/api/cn/traffic`：`cells[].lat/lng` 是服务端按**你传的 bbox 等分算出的格心**（`cn-live.js:97` `trafficGrid`），不是上游返回的坐标 —— **坐标系与你传的 bbox 一致**。传 WGS-84 视口就按 WGS-84 画，**不要再逆变换**（再转会整体偏约 500m）。代价是采样点在高德侧有 ~500m 偏移；路况是网格级面状信息，不影响判读，**默认接受，不要为消除它引入 bbox 双向转换**（四角转 GCJ-02 后再等分网格并不等价，风险大于收益）。
     ⚠️ 小程序 `cn.js:68` 硬编码 `crs:'gcj02'`，因为腾讯地图视口本身就是 GCJ-02 —— **照抄这行会让网页版整体偏 500m**。
