### 1.2 改前首屏关键路径（C6 冷启动实测，gate 相对 ms）

```
frame:first 819–1062
  → tileset:added 2494–3545        ← await Tiles（root.json + 瓦片集解析）
  → cine:go 2532–3550              ← 相机被 tileset 卡住
  → cine:done 6795–8807            ← 快定位 ≤2.5s + GPS 纠偏 3s
  → view:content 10290–12345       ← 最终视角等 Tiles 细化到清晰
  → view:settled +700
  → mask:gone 11082–13294          ← 墙钟 loading 12.5–17.2s
```

结论：**3D Tiles 与首屏交互死绑**（`scene.js` await）——它把 `controls/data/tools`（含 9 张玻璃卡）、相机落位、就绪门全部推到 Tiles 之后，而 Tiles 只是「最终画质」，不是「可交互」的前提。

## 4. 未达成项与根因（按收益排序）

1. **底图瓦片到最终视角 1.6–3.9s（最大项）**：`jumpTo` 后才向 AMap/Esri 请求 12km 视角的瓦片。修法已明确：用 `tileWarmup.announceBootCenter` 的同一中心，按 WebMercator 反算 12km 视角需要的 z/x/y（约 3×3～4×4 张），在**遮罩期内**用 `<img>`/fetch 预取进 HTTP 缓存 → 落位后同 URL 直接命中缓存（预计省 1.5–3s）。
2. **dev 模块图 4.7s**：prod 打包后显著降低（C6 实测 dev→prod 差 2.5–3s）；本轮未在硬停前重建 prod + 6 跑。
3. **进入后仍有 >100ms 单帧（3/5）**：photoreal 现在**有意**挪到交互后，model shader link / 瓦片上传的长帧从「遮罩后面」变成「可见」。当前用 `RequestScheduler` 2/4 限流削峰（`armPhotorealWatch`），仍不够。下一步可在升级前用 `tileset.preloadWhenHidden`+隐藏预热，或把升级延后到 `requestIdleCallback`，并接受「首次升级一次长帧」与卡面要求之间的取舍（需 lead 决策：≤5s 与无 >100ms 在物理上互相拉扯）。
4. **`startupChrome` 1s 最短展示 + styleManager 恢复**：mask:hide-request 在 `chrome:begin+1s` 才发生，是最后 ~1s 的地板之一（刻意保留的 UX，不建议删）。

## 2. 关键证据：底图真正的瓶颈是「逐级爬金字塔」，不是网络总量

`img1-imagery.json`（prod 4174，改前）：相机落位后请求序列

```
z1@5141(8块) → z2@5791(4) → z3/4@5949(4+4) → z11@6941(4) → z13@7113(16) → view:content 7566
```

- 每一级都等上一级的瓦片回来才进下一级，13 级串成 **2.2s**；
- 真正决定「中心 640×420 清晰」的只有 z13 那 16 块，**到齐只用 450ms**；
- 预取把单块瓦片耗时从 **433–515ms 降到 117–159ms**（`ab0` vs `abchain` 的 z13 dur 分布），
  但**端到端没增益**：Cesium 的逐级细化还要吃渲染帧，每级固定 ~500ms，
  网络只占其中一部分。

## 5. 为什么 ≤5s 在物理上到不了（按阶段分解，run1 of B）

```
responseStart 36 → domInteractive 3272   ← HTML+CSS+模块图（2.7MB index chunk）
  → 首帧 1671 → setStack 1284            ← Esri 服务元数据 827ms（走代理）
  → 落位 600 → 底图金字塔到 z13 2873    ← Cesium 逐级细化，13 级
  → SETTLE 721（探针要求连续 700ms 达标）
  → 淡出 231 → mask:gone = 12.4s
```

要 ≤5s 必须砍掉其中至少 7s。可选杠杆（都会碰到产品定义，需要 lead 决策）：

1. **模块图 2–3.3s**：`index` 2.67MB + `egm96` 2.77MB（已动态 import）+ `regions` 1.99MB。
   可做 manualChunks 拆分 + `modulepreload`，预计省 0.8–1.8s，**不动画质**。
2. **Esri 元数据 827ms**：大陆用户默认走 AMap（无元数据往返），本机因能连 Google 才吃这 0.8s。
3. **底图金字塔 2.9s**：要更快只能降低落位后的清晰度档（如放行 z10 上采样）＝画质回退，**违反 B5/不降级**。
4. **SETTLE 700ms + 淡出 230ms**：改判据＝改验收口径。
5. **photoreal 挪回遮罩期**：会重新把 3D Tiles 绑回首屏（本卡明令禁止）。

结论：**「交互 ≤5s」与「收遮罩时中心清晰影像（B5）+ 不降级」在本机实测下互斥**，
最好一批 8.1s。要么放宽画质/判据，要么把 5s 重新定义为「首帧+卡片可点」（当前首帧 1.7–2.0s）。
